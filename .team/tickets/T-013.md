# T-013: Require Add to Home Screen on iPhone and iPad

## Goal
On an iPhone or iPad, Email's Gym only works when opened from the Home Screen: notifications
need it, and it runs full screen like an app. Emil decided (2026-11-10) to require it:

- On iOS/iPadOS in a browser (not standalone), once someone is **signed in**, the app shows only
  an install screen instead of the app: the slab E (`components/BrandMark.jsx`), a heading
  ("Add Email’s Gym to your Home Screen"), the steps for Safari (tap Share, then "Add to Home
  Screen", then open it from there), one plain line on why (notifications and full screen), and a
  quiet note: "An App Store version is in development."
- Signing in, creating a profile and redeeming an invite code still happen in the browser first
  (passkeys are saved there); the screen comes right after.
- Opened from the Home Screen (`display-mode: standalone` / `navigator.standalone`), it never shows.
- On a computer (and anything that is not iOS/iPadOS), nothing changes: the web app works in
  the browser as now.
- Inside the native app build (`MOBILE`), nothing changes.
- A signed-out visitor in iOS Safari sees the sign-in screen as now (they need it to sign up).

## Context
- The app already detects these: look for `standalone()`, `APPLE_UA`, `IS_ANDROID` and the
  `installTip` / "Add to Home screen" tip in `frontend/src/views/Settings.jsx` and their helpers in
  `frontend/src/lib/`. Reuse them; put the decision ("show the install screen?") in a pure helper
  in `frontend/src/lib/` with a test covering: iPhone Safari signed in, iPhone standalone, iPad
  (desktop-class Safari reports a Mac user agent: use touch points, as the existing helper does if
  it handles it), iPhone signed out, a Mac, the MOBILE build.
- Route the screen from `frontend/src/App.jsx` where the signed-in app renders; keep the rest of
  the app unmounted behind it.
- Style with the existing tokens and components (`index.css`, `Button`, `BrandMark`); 44 px
  targets; text through `t()`, plain, no em dashes.
