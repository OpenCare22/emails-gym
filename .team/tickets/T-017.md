# T-017: Find a program for me (questionnaire and matching)

## Goal
Route B of the master plan (`docs/emails-gym-planning/CLAUDE_CODE_MASTER_PLAN.md` §2 and §5,
`research/B-training-methodology.md`, `research/E-claude-code-spec.md` "Program matching"): a short
multiple-choice questionnaire that picks up to three programs from the library, explains why each
fits, and never invents a plan. Fixed, testable rules: no AI. Needs T-016 merged.

### The questions (one per screen, Back always available, progress "2 of 7")
1. Main goal: Build muscle / Get stronger / General fitness / Strength and cardio / Cardio fitness /
   Short sessions. One plain line under each.
2. Experience: Beginner (under 6 months of regular training) / Intermediate (6 months to 2 years,
   comfortable with the main lifts) / Advanced (over 2 years).
3. Days a week you can train: 2 / 3 / 4 / 5 or more.
4. Time per session: 30 / 45 / 60 / 90 min or more.
5. Where you train: Full gym / Dumbbells only / No equipment. Prefill from the active gym profile
   (`lib/equipment.js profileEquipment`) when there is one.
6. Cardio: As much as possible / Some / As little as possible.
7. "Do you have an injury, a health condition, or has a doctor told you to limit exercise?" Yes / No.

### Matching (`frontend/src/lib/program-match.js`, pure, + `program-match.test.js`)
`matchPrograms(answers, programs, { admin })` → `{ version, matches: [{ program, score, why: [],
compromises: [] }], excluded: [{ program, reasons: [] }], advice }`. `MATCH_VERSION = 1` exported.
- Only programs `isVisible` for this user (`lib/library.js`).
- **Hard filters first** (any one excludes, with the reason kept):
  - Answer 7 is Yes → no matches at all; `advice: 'professional'`. The screen says: "Talk to a
    doctor or physiotherapist before starting a new program. You can still build your own routine."
    with a button to Routines. No program is suggested.
  - Program days > the user's days (5 or more counts as 5).
  - Program equipment not available: Full gym allows everything; Dumbbells only allows
    `dumbbell` and `body weight`; No equipment allows `body weight` only.
  - The program's longest estimated session (`minutes[1]`) more than 10 minutes over the user's time
    (90 or more never excludes).
  - Level: a beginner is not matched to an intermediate-only program; an advanced user can take an
    intermediate program; `any` fits everyone.
- **Score** the rest (product weights, not science; keep them in one exported object with the
  version): goal match +40; days exactly equal +25; longest session within the time +15; level
  fits exactly +15; cardio preference fits (much: hybrid or endurance goal; little: no cardio
  sessions) +5. Ties broken by fewer days, then id, so the same answers always give the same order.
- `why`: plain sentences built from what scored ("Built for muscle growth", "4 days, as you
  asked", "Sessions about 45 to 60 min"). `compromises`: what didn't ("3 days instead of the 4 you
  have", "Longest session about 70 min, a bit over your 60").
- No matches → `matches: []`; the screen says: "No program fits these answers yet." with Change
  answers and Build your own routine buttons. Never a nearest-wrong suggestion.
- Answers are not stored or synced; a reload starts over.

### Tests (must include the master plan's §5 fixtures, against the real library data, treating
all programs as approved for the test)
- Intermediate, 4 days, full gym, 90 min or more, muscle → build-4 first (and with 60 min, say in
  the report whether build-4's estimate still fits).
- Beginner, 2 days, dumbbells only → no commercial-gym plan (no match is fine).
- Beginner, 2 days, full gym → foundation-2 first.
- 5 days, no equipment → no match.
- Health answer Yes → no matches, advice professional.
- Same answers twice → identical result. Non-approved programs invisible to a non-admin.

### Screens

  `/programs` (T-016's list). Results as cards like the list's, with the `why` lines and
  compromises, each opening `/programs/:id`.
- Text through `t()`, plain, no em dashes, 44 px targets, existing tokens and components.
