# T-007: Hide progress photos, structural balance, data imports and audit logging

## Goal
Hide these four features from the app without deleting their code, so they can come back with a
one-line change if they are missed. After a week or two of use they will be deleted or restored.

## Context
- Routes in `frontend/src/App.jsx`: `/progress-photos` (behind `isOn(S, 'body')`) and
  `/structural-balance`. Links to them live in views such as Stats, Measurements, Muscles, Home,
  and in Settings.
- The app has a modules system (`isOn(S, ...)`, `lib/modules*.js`, `docs/MODULES.md`). Prefer one
  fork-level switch, e.g. a small `frontend/src/lib/fork-hidden.js` exporting a set of hidden
  feature ids, checked where each entry point is rendered, so un-hiding is a one-line edit.
- Data imports: importers from Strong, Hevy, FitNotes etc. (Settings → data, `docs/DATA_IMPORTS.md`,
  `lib/import*.js`). Hide the import entry points; keep export and backup/restore visible.
- Audit logging: `AUDIT_*` env vars in the api. Make sure it is off by default and remove any
  user-facing or admin UI that only shows audit logs. Don't remove the api code.
- Hidden routes should redirect to `/home`, not 404.

## Allowed files
- frontend/src/App.jsx
- frontend/src/lib/fork-hidden.js
- frontend/src/lib/fork-hidden.test.js
- frontend/src/lib/modules*.js
- frontend/src/views/**
- frontend/src/components/**
- frontend/src/App*.test.jsx
- api/**
- .env.example

Notes on allowed files:
- `fork-hidden.js` and its test are new.
- `views/**`, `components/**`: only to hide entry points, and their tests.
- `modules*`: only if that's the cleaner place for the switch.
- `api/**`, `.env.example`: only if audit logging is on by default (turn it off), audit wording.

## Forbidden files
Everything else. Don't delete the hidden views, lib helpers or their tests.

## Rules
Follow AGENTS.md. Existing tests for the hidden views must keep passing (they render the
components directly). Update tests that assert a link is visible.

## Acceptance
- sh scripts/fork/check.sh

## Report
- New tests: each hidden feature has no entry point in the main screens and its route redirects
  to `/home`; flipping the switch brings the entry point back.
- In your result: where the switch lives, every entry point you hid, and the check results.

## Out of scope
Deleting code, restyling, the new navigation (Phase 2).
