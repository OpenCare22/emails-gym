# T-028: Friends 1: groups, invite links, sharing settings and shared summaries (server)

## Goal
PLAN.md Phase 7 items 1 and 2, server side only. Friends join a group with an invite link; each
person chooses, per metric, what that group sees; the server keeps a small **summary** per person,
computed when their state is saved, and the social features read only those summaries, never
another person's `state-<uid>.json`. The default is that nothing is shared.

### Module `api/social/` (new), wired from `api/server.js`
- Storage: `DATA_DIR/social/social.json` (groups, memberships, sharing) and
  `DATA_DIR/social/summaries/<uid>.json`, written with `atomicWrite` (`api/durable.js`), mode 0600.
  Nothing in `db.json`. `removeUser(uid)` drops their memberships, sharing and summary (wire it in
  `removeAccount` in server.js next to the integrations and health ones). A group whose owner leaves
  passes to its longest-standing member; an empty group is deleted.
- Group: `{ id, name (1-40 chars), ownerId, members: [{ uid, joinedAt }], invite: { code, expiresAt } | null }`,
  at most 12 members, a person in at most 5 groups. Invite code: 16 url-safe random chars, valid
  14 days, the owner can make a new one (the old one stops working) or turn it off.
- Sharing, per person per group: `{ workouts, streak, volume, prs, steps, activeMinutes, strength, feed }`
  booleans, all false until the person sets them. `nudges: true|false` per person (receive nudges at
  all, default true).
- Summary (pure `summaryOf(state, { now, tz, weekStart })` in `api/social/summary.js` + tests):
  `{ updatedAt, week: '<YYYY-Www in the person's weeks>', workoutsWeek, workoutsMonth, workoutsAll,
  streakWeeks, bestStreakWeeks, volumeWeekKg, volumeMonthKg, prsMonth, stepsWeek, activeMinutesWeek,
  strength: { squat, bench, deadlift } }` where strength is the best estimated 1RM in the last 90 days
  (Epley, sets of 1 to 10 reps, work sets only) divided by the latest body weight, for the catalogue
  ids the app treats as those lifts (read `frontend/src/lib/strength-level.js` or `relative-strength.js`
  for the ids and copy them). Volume in kg whatever the profile unit. Steps and active minutes come
  from the person's own health files (`api/health/` Google `describe(uid).data` and Apple), not from
  state. The week streak **must match** `frontend/src/lib/streak.js` exactly (freezes included): copy
  its rules into `api/social/streak.js` and add a parity test that runs both on the same fixtures
  (the API test may import the frontend file by relative path, as `api/test/sync-stamps` parity
  tests do; check how they do it). Time zone from the state's `reminder.tz` (fallback UTC), week start
  from `weekStart` (1 Monday, 0 Sunday).
- Recomputed in the `PUT /api/data` handler after a successful write (next to
  `integrations.onStateWrite`), never failing the save, and once a day by a tick for everyone in a
  group (so a new week resets "this week" without a save).

### Routes (`api/social/routes.js`, documented in `api/openapi.yaml` under a new tag `social`)
All need a session. Errors as `{ error, code }`.
- `GET /api/social` → `{ groups: [{ id, name, owner: bool, members: [{ uid, name, self }], invite? (owner only) }], sharing: { [groupId]: {...} }, nudges }`. Member names are the profile names (`publicUser`).
- `POST /api/social/groups` `{ name }` → the new group with an invite.
- `POST /api/social/groups/invite` `{ groupId, off? }` (owner) → `{ code, expiresAt }` or off.
- `GET /api/social/invite/:code` is not needed; instead `POST /api/social/join` `{ code }` → the group
  (404 `invite-invalid` for unknown/expired, 409 `full` / `too-many-groups`, joining twice is a no-op).
  Rate limit joins to 10 tries an hour per profile (`api/rate-limit.js`).
- `POST /api/social/leave` `{ groupId }`; `POST /api/social/remove` `{ groupId, uid }` (owner).
- `POST /api/social/sharing` `{ groupId, sharing: {...} }` (only the known keys, booleans) and
  `POST /api/social/nudges` `{ on }`.
- `GET /api/social/summary` → the caller's own summary (for the app to show "what others will see").

### Tests (`api/test/social.test.js`, `api/test/social-summary.test.js`)
Group lifecycle (create, invite, join, expired code, full, leave, owner leaves, remove), sharing
validation, a profile in no group exposes nothing, summary numbers on a fixture state (week
boundary in another time zone, Sunday weeks, lb profile volume in kg, strength ratio), the streak
parity test, removeUser.
