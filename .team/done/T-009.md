# T-009: Restyle the Focus view to the Email's Gym workout render

## Goal
Make the Focus view (one set at a time, the default since T-008) match the approved workout
render (`design/emails_gym_workout_render.png`) and the handoff
(`design/EMAILS_GYM_CLAUDE_CODE_HANDOFF.md` §4B), without changing the workout logic. Four parts:

1. **Hierarchy and look.** Top to bottom: the exercise as a centred heading (`--fs-title3`,
   weight 700) with "Set 3 of 4" under it; the load stepper and the reps stepper each in their own
   rounded card (`--surface`, `--r-card`), the number large (40-48px, weight 700, tabular), the
   unit small beside it, − and + as at least 44×44 px targets; then the dominant **Complete set**
   button (the existing primary, off-white). Cardio (duration, speed, incline), timed holds,
   per-side sets, drops and bursts keep working and get the same card treatment.
2. **Previous performance as a subtle hint.** Under "Set 3 of 4", in `--label-3`: the same set
   from the last session of this exercise, e.g. "Last time: 100 kg × 8". Use `lastEntryFor`
   (already imported in FocusView.jsx); nothing when there is no last time.
3. **Undo after completing a set.** Completing a set in the Focus view shows the existing toast
   with an Undo action (the same toast API `removeSet` uses in Workout.jsx, `ui.toast(msg,
   { action, onAction })`). Undo un-completes that set and stops the rest timer that completion
   started, and nothing else. A pure helper in `frontend/src/lib/` with a test if any logic is
   involved.
4. **Rest timer as a card in the Focus view.** While a rest runs in the Focus view, show it as a
   rounded card like the render: a progress ring (SVG, `--acc` on a `--surface-2` track), the
   time left as large `m:ss` (tabular), "Rest" under it, and the existing pause/resume and skip
   controls (44 px targets). Read the existing rest state (`useUI` `timer`: `endsAt`, `total`,
   `left`, `paused`) — do not change how it counts (it uses absolute timestamps; keep it so). The
   bottom `#timer` bar stays as it is in the other views. Respect `prefers-reduced-motion` (no
   ring animation, just the value).

Keep the heart-rate display as it is: there is no live heart rate on the web app (correction 2 in
`docs/fork/DESIGN_PLAN.md`).
