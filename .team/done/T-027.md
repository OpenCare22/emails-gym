# T-027: Apple Watch data through Health Auto Export (Phase 4b)

## Goal
PLAN.md Phase 4b: friends with an Apple Watch send their Apple Health data to our server with the iOS
app **Health Auto Export** (its REST API automation, Premium tier), into the same normalised data as
Google Health, so Home, Progress and later the leaderboards treat both alike.

### What Health Auto Export sends (its Help Center, help.healthyapps.dev, read 2026-11-10)
- A POST with `Content-Type: application/json` and any headers the user adds; we ask them to add
  `Authorization: Bearer <token>`. With "Batch Requests" on, one export may arrive as several POSTs.
- Body: `{ "data": { "metrics": [...], "workouts": [...] } }` (older versions: `{ "metrics", "workouts" }`
  at the top level; accept both).
- Metric: `{ "name": "step_count", "units": "count", "data": [{ "qty": 8500, "date": "2024-02-06 14:30:00 -0800", "source": "Apple Watch" }] }`.
  Names are snake_case. Documented: `step_count`, `heart_rate` (items have `Min`, `Avg`, `Max`
  instead of `qty`), `active_energy`, `sleep_analysis` (units hr; summarised items carry
  `totalSleep`, `asleep`, `core`, `deep`, `rem`, `sleepStart`, `sleepEnd`, `inBed`; unsummarised items
  carry `start`, `end`, `qty` hours and `value` "Asleep" | "Core" | "REM" | "Deep" | "Awake" | "In Bed").
  **Not documented, so accept these and log anything else**: `resting_heart_rate`, `body_mass`
  (units kg or lb), `apple_exercise_time` (min). Dates are `yyyy-MM-dd HH:mm:ss Z`.
- Workout (export version 2): `{ id, name, start, end, duration (s), distance: { qty, units },
  activeEnergyBurned: { qty, units }, avgHeartRate: { qty }, maxHeartRate: { qty },
  heartRateData: [{ date, Min, Avg, Max }] }`. Version 1 has no id or duration and
  `heartRateData: [{ date, qty }]`; derive an id from name + start.

### Build
1. **Server** (`api/health/apple.js` + routes in `api/health/routes.js`):
   - `POST /api/apple-health/token` (session): makes a new ingest token (random, shown once), stores
     only its SHA-256 per profile, replacing any old one. `DELETE`-style `POST /api/apple-health/disconnect`
     removes the token and the data. `GET /api/apple-health` (session): `{ connected, lastReceived,
     unknownMetrics: [names], data }` in the normalised shape of `api/health/data.js` with
     `source: 'apple'` (steps by day as the sum of `step_count` per local day; restingHr by day;
     sleep by night as minutes from `totalSleep` or summed asleep segments; weight list in kg;
     exercise list like Google's, `avgHr` from `avgHeartRate` or the mean of `heartRateData`;
     activeMinutes from `apple_exercise_time`).
   - `POST /api/apple-health/ingest`: **no session**; `Authorization: Bearer <token>` looked up by hash
     (constant-time); 401 without a valid token. Body capped at 5 MB (413 above), rate limited to
     60 requests an hour per token (`api/rate-limit.js`), answers `{ ok: true, received: { metrics, workouts } }`.
     Idempotent: the same export twice changes nothing (days are replaced, workouts and weights
     deduped by id). Metric names it doesn't know go into `unknownMetrics` (capped at 30).
     Workout heart-rate samples are kept per workout (`hrSamples: [{ t, bpm }]`, at most 1 per 5 s)
     so a gym session can be filled like T-024 does for Google.
   - Stored in `DATA_DIR/health/apple-<uid>.json` (0600), 400 days, removed with the profile
     (`removeUser`, wired in `api/server.js` where Google Health's is).
   - Make sure the CSRF check in `api/server.js` lets the ingest route through (it has no browser
     Origin; check `csrfOk` and add it to the exemptions only if needed), and that `readSession` is
     never consulted for it.
   - `api/openapi.yaml` (tag health) and `api/test/health-apple.test.js`: token auth, both body
     shapes, v1 and v2 workouts, sleep summarised and not, unknown names, a duplicate POST, 413, 429.
2. **App**:
   - Settings → Integrations, web app (`views/Integrations.jsx`, a new `components/AppleHealthExportCard.jsx`):
     an "Apple Watch" card with numbered steps: install Health Auto Export, Premium, Automations →
     new REST API automation, URL `https://<this server>/api/apple-health/ingest` (copy button),
     header `Authorization` = `Bearer <token>` (made with a **Create key** button, shown once with a
     copy button), Data: Health Metrics (step count, resting heart rate, heart rate, sleep analysis,
     body mass, apple exercise time) and Workouts (export version 2), Summarize Data on,
     Date range "Since Last Sync", sync every 1 hour. Then "Last received: …", a gentle warning when
     nothing has arrived for 2 days ("iPhone only sends while unlocked; open Health Auto Export
     once"), the unknown metric names if any, **New key** and **Disconnect**. Replace the line
     "Apple Watch and Apple Health come with the Email's Gym iPhone app…" with this card.
   - `frontend/src/lib/google-health.js`: also load `/api/apple-health` and expose one merged `data`
     for Home and Progress (per day: Google's value when both exist), weigh-ins from both
     (`src: 'apple'` for Apple's), the heart-rate fill from Apple workout samples too. Keep the
     existing exports working.
   - `views/settings-pages.js`: a search entry "Apple Watch" for the card.
   - Tests for the merge, the card states (no key, key just made, receiving, stale, unknown metrics).
