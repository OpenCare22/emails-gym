# T-010: Step 6 fixes: 44 px hit areas, a missing switch name, a light boot screen

## Goal
Fix what the Phase 2 step 6 audit found (docs/fork/DESIGN_PLAN.md step 6; the handoff's §5 asks for
a real 44×44 px hit region on every control, not only a visual one). Three parts:

1. **44 px hit areas without changing how things look.** Measured at 375, 390 and 430 px wide,
   these controls are smaller than 44×44 px:
   - `.iconbtn` everywhere (36×36): page headers, Friends' invite, Stats, Measurements
   - Home's week arrows (30×30, the `.iconbtn` with an inline 30 px size in `views/Home.jsx`)
   - Exercises' `.iconbtn.lib-add` (32×32)
   - the accent swatches on Settings → Look (`.swatch`, 32×32)
   - the workout header's `.whdr-map` (39×32) and the set chips `.wchip` (28×28)
   Grow the tappable area to at least 44×44 px, keeping the drawn size: e.g. a transparent
   `::after` (or `::before`, whichever the element does not already use) with a negative inset
   on a `position:relative` element, or padding with a negative margin. Check each rule's existing
   pseudo-elements first so nothing visible changes, and that neighbouring hit areas do not
   overlap so a tap could land on the wrong control.
2. **Switches without a name.** On Settings → Look the "Body weight" switch (`role="switch"`) has
   no accessible name, while its neighbours have one (`aria-label` from their row title). Find
   every `Switch` use in `frontend/src` that renders without an accessible name and give it the
   row's title. Add a test that renders Settings → Look and asserts every visible
   `[role="switch"]` has a name.
3. **The boot screen in the light theme.** `frontend/index.html`'s boot screen is always the dark
   near-black, so a light-theme profile flashes dark at launch. Make it follow the saved theme:
   the head script already reads `gym_state_v1` from localStorage; have it set
   `data-theme="light"` on `<html>` early when `s.theme === 'light'` (or `'system'` with a light
   `prefers-color-scheme`), and give `#boot` light colours under that attribute (background
   `#f8f9f7`, the mark `#161b17`; the fail state's text/code/button in the light tokens). The
   inline script's hash changes, so update `web/Dockerfile`'s CSP `script-src` hash;
   `frontend/src/lib/csp.test.js` checks it. Keep the script in plain old syntax (it must run
   where the bundle cannot, see the comment above it).
