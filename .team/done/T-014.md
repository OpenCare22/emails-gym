# T-014: Programme weeks that change sets and RIR

## Goal
A programme (`lib/programmes.js`) runs your routines for 1 to 16 weeks, but its weeks can only
change the load: a %1RM or an RPE per exercise, a week-wide RPE, a deload. Real blocks also change
how many sets you do and how hard (week 1 one set at RIR 4, later weeks more sets at RIR 1).
Add both, per exercise per week, without changing anything for programmes that don't use them.
This is the first step of the workout library (docs/emails-gym-planning/REPO_AUDIT.md, "Proposed
first PR").

- Week targets `t[key]` (key = `exId` or `rid:exId`, as today) accept two optional fields next to
  `pct` and `rpe`: `sets` (integer 1 to 10) and `rir` (0 to 5, half steps); and for cardio slots
  `min` (1 to 300, whole minutes) and, for any slot, `note` (trimmed, up to 200 characters). Out-of-range or wrong
  types are dropped, as `cleanPct` / `cleanRpe` drop theirs. A target with only `sets`, or only
  `rir`, is valid. `rir` and `rpe` on the same target: keep `rpe`, drop `rir` (one scale per
  target, like a set's `rir` XOR `rpe`).
- `cleanWeek`, `normalizeProgramme`, copying a week (`out.push({ ...clone(last) })`),
  `bundleProgramme` and `importedProgramme` keep the new fields (plan files carry them; import still
  bounded by IMPORT_MAX_TARGETS).
- While the programme runs, `session-start.js` builds the slot with the week's `sets` in place of
  the routine's set count (work sets only; warm-ups unchanged), and shows `rir` as the target the
  way an RPE target is shown today (`rpeAs` turns it into the profile's effort scale: an RIR
  profile sees "RIR 2", an RPE profile "RPE 8"). The weight still comes from `pct` or the policy.
- A cardio slot with a week `min` opens at that duration (speed from the routine/history as now).
  A week `note` is shown on the exercise in the workout for that week, like the routine's own note
  (e.g. "6 min easy, 3 rounds of 2 min hard and 3 min easy, 4 min easy").
- A deload week keeps working as now; a deload week with `sets` uses those sets.
- Progression reads hits against the sets the session asked for (check `lib/progression.js`
  counts done sets against the entry's own target, and add a test that a 1-set week 1 is not read
  as 2 missed sets).
- The programme editor (`views/Programmes.jsx`, `ProgrammeEdit`) shows a Sets stepper and an
  effort target (RIR or RPE, by the profile's effort setting) per exercise per week, next to the
  %1RM it has. Empty means "as the routine". 44 px targets, text through `t()`, plain, no em dashes.
- No other behaviour changes. A programme without the new fields builds byte-for-byte the same
  sessions as before (test it).
